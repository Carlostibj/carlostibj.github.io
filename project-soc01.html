THE OBJECTIVE

Build visibility before writing detections

After the infrastructure was stable, I added the monitoring layer. SOC01 brings Windows and Linux endpoint telemetry, passive network traffic, IDS alerts, and network metadata into one place through Wazuh.

I stopped SOC01 at the telemetry platform. Instead of forcing every detection idea into one oversized project, I'm using this environment as the base for smaller detection, hunting, and investigation labs.

SKILLS DEMONSTRATED

Security engineering applied in this project

Wazuh administration and agent enrollment, Windows Advanced Audit Policy, Event ID 4688 command-line logging, Sysmon and Group Policy rollout, Linux journald, SSH, sudo and auditd, Suricata IDS, Zeek network metadata, JSON log pipelines, passive packet capture, Proxmox Linux bridges, tc/mirred traffic mirroring, systemd persistence, Bash automation, and troubleshooting.

THE DESIGN

Endpoint telemetry with a separate passive sensor

WAZUH01 remains the central analysis layer on the Monitoring LAN. SENSOR01 is an Ubuntu VM with two VirtIO interfaces: a management interface at 10.10.30.110 and an addressless sniffing interface. Proxmox copies selected VM traffic into a dedicated mirror-only bridge without placing SENSOR01 inline.

Passive by design: SENSOR01 never sits in the traffic path. If I shut the sensor down, the rest of the lab keeps working. Proxmox hooks rebuild the mirror rules automatically when monitored VMs or SENSOR01 restart.

TELEMETRY ENGINEERING

Coverage across Windows, Linux, and the network

Windows audit + Sysmon

Advanced Audit Policy gives me authentication, account and group changes, process creation, and policy-change events. I also enabled command-line data for Event ID 4688 and used a focused Sysmon configuration for additional process, network, file, registry, DNS, WMI, and tampering context.

Linux journald + auditd

WAZUH01 collects sudo and SSH activity through journald. I added focused auditd watches for identity files, sudoers, cron, systemd paths, and SSH configuration.

Suricata IDS

Suricata 8.0.7 runs on SENSOR01 through ens19 using AF_PACKET. Wazuh Agent 007 collects EVE JSON. I used a simple controlled ICMP rule to prove the alert could travel from mirrored traffic all the way into Wazuh rule 86601.

Zeek metadata

Zeek 8.0.10 analyzes the same mirrored packets and records connection and DNS activity. I switched conn.log and dns.log to JSON and added both files to the SENSOR01 Wazuh agent configuration.

ENGINEERING LESSONS

Issues I had to work through

Time synchronization before correlation

I fixed time synchronization before relying on event correlation. DC01 became the domain time source, and the Windows members synchronized through the domain as expected.

Malformed Wazuh agent XML

A bad closing tag in FILE01's Wazuh configuration stopped the agent service. The agent logs pointed to the XML error, and I fixed the configuration without reinstalling anything.

Persistent virtual traffic mirroring

Proxmox TAP interfaces only exist while their VMs are running, so a one-time tc rule was not enough. I added lifecycle hooks that remove and rebuild the mirror rules automatically as systems stop and start.

Suricata startup failure

The Suricata package expected eth0, but SENSOR01 uses ens19 for sniffing. It also started without the rules file I needed. Pointing AF_PACKET to ens19 and running suricata-update fixed both issues.

Collection is not the same as detection

One thing I had to keep straight was the difference between generating an event, collecting it, decoding it, matching a rule, and finally seeing an alert in the dashboard. Treating those as separate steps made troubleshooting much easier.

The biggest takeaway for me was that installing tools is the easy part. The real work is making sure time, endpoint policy, packet visibility, parsing, transport, and validation all line up.

PROJECT OUTCOME

A SOC platform I can reuse for future labs.

SOC01 is now frozen as the monitoring foundation. The next project, DET01, will use this environment for authentication attack detection and investigation instead of adding more infrastructure to SOC01.
