THE OBJECTIVE

Build trustworthy visibility before deeper detections

I extended the validated INFRA-BASE-v1 environment into an enterprise-style security monitoring platform. Windows and Linux telemetry, passive network visibility, IDS alerts, and network metadata are centralized through Wazuh.

The project deliberately stops at the telemetry-platform boundary. Deeper detection engineering, tuning, ATT&CK mapping, hunting, and investigation are separated into focused follow-on projects so each portfolio case study has a clear purpose.

THE DESIGN

Endpoint telemetry plus an out-of-band network sensor

WAZUH01 remains the central analysis layer on the Monitoring LAN. SENSOR01 is an Ubuntu VM with two VirtIO interfaces: a management interface at 10.10.30.110 and an addressless sniffing interface. Proxmox copies selected VM traffic into a dedicated mirror-only bridge without placing SENSOR01 inline.

TELEMETRY ENGINEERING

Coverage across Windows, Linux, and the network

Windows audit + Sysmon

Advanced Audit Policy captures authentication, account/group changes, process creation, and policy changes. Command-line inclusion enriches Event ID 4688; a focused Sysmon configuration adds process, network, file, registry, DNS, WMI, and tampering context.

Linux journald + auditd

WAZUH01 collects sudo and SSH activity through journald. Focused auditd watches cover identity files, sudoers, cron persistence, systemd paths, and SSH configuration.

Suricata IDS

Suricata 8.0.7 runs on SENSOR01 ens19 using AF_PACKET. EVE JSON is collected by Wazuh Agent 007. A controlled ICMP signature validated the complete alert pipeline into Wazuh rule 86601.

Zeek metadata

Zeek 8.0.10 produces structured connection and DNS telemetry from the same mirrored packets. conn.log and dns.log are emitted as JSON and collected by the SENSOR01 Wazuh agent.

ENGINEERING LESSONS

Problems I traced to their cause

Time synchronization before correlation

Windows and Linux timestamps were normalized before trusting event correlation. DC01 became the domain time authority and domain members synchronized through the expected hierarchy.

Malformed Wazuh agent XML

A closing-tag typo stopped the FILE01 agent service. Agent logs identified the XML parsing failure and the configuration was repaired without reinstalling the agent.

Persistent virtual traffic mirroring

TAP interfaces only exist while VMs run. I used Proxmox lifecycle hooks so tc/mirred rules are automatically removed and recreated as systems stop and start.

Suricata startup failure

The package default expected eth0 and initially had no rules file. Binding AF_PACKET to ens19 and running suricata-update restored a healthy service.

Collection is not the same as detection

Several troubleshooting steps reinforced the difference between generating telemetry, collecting it, decoding it, matching a rule, and indexing an alert. That distinction prevented false diagnoses.

The main lesson: a SOC platform is an engineered chain of time, endpoint policy, packet access, parsing, transport, and validation—not a collection of installed tools.

PROJECT OUTCOME

A reusable SOC foundation for focused detection labs.

SOC01 is frozen as a validated telemetry platform. The next portfolio project, DET01, will use this environment for authentication attack detection and investigation instead of expanding SOC01 indefinitely.
