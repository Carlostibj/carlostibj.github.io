THE OBJECTIVE

A reliable baseline before SOC work

I designed and deployed an enterprise-style environment to understand the infrastructure that security monitoring depends on: routing, identity, DNS, policy, permissions, and recovery. The goal was to establish a known-good starting point for future telemetry and detection projects.

I configured the services, validated allowed and denied access paths, corrected failures during the build, and repeated critical checks after a controlled host reboot.

THE DESIGN

Separated networks. Clear ownership.

OPNsense is the sole Layer-3 gateway for routed lab networks. Proxmox internal bridges provide Layer-2 connectivity. Servers and monitoring have dedicated networks; IT, Sales, HR, and Marketing each have a VLAN.

IMPLEMENTATION

Controls I configured

Service-based firewall policy

Explicit allows for required internal services, followed by private-network denies and Internet egress. Rule ordering preserves necessary access while restricting cross-network traffic.

Centralized identity & policy

The homelab.internal domain includes departmental OUs, uniquely named workstations, and Group Policy. Domain trust and DNS health were checked.

Department file permissions

AGDLP-style group nesting separates users from resource permissions. NTFS permissions enforce department access; matching users succeed and cross-department access is denied.

Monitoring foundation

Wazuh was deployed on a dedicated Ubuntu monitoring server. Required service paths and administrative dashboard access were validated.

Scope of this milestone: Wazuh deployment and reachability are part of INFRA-BASE-v1. Agent enrollment, Sysmon telemetry, detection tuning, and incident-response exercises belong to subsequent SOC work.

A separate recovery copy

With all VMs shut down, I created ZSTD-compressed VZDump backups for all eight core VMs on a dedicated external 2 TB ext4 disk. These backups are the recovery copy; local snapshots are only convenient rollback points.

The documented recovery validation covers reboot and service recovery. A full restore exercise is not claimed here.

ENGINEERING LESSONS

Problems I traced to their cause

Duplicate gateway ownership

Proxmox bridges carried gateway addresses that conflicted with OPNsense. I changed the bridges to Layer 2 only, leaving OPNsense as the sole routed gateway.

Marketing DHCP failure

The VLAN used the wrong OPNsense parent interface. Correcting the parent restored DHCP and stable connectivity.

Cloned Windows computer identities

Duplicate identities caused machine-account trust failures. I assigned unique hostnames, repaired secure channels, and documented generalization for future templates.

Group Policy processing stalled

The dynamic RPC firewall range was represented incorrectly. Correcting the rule restored normal gpupdate processing.

Wazuh installation ran out of storage

Ubuntu was not using the full virtual disk. Extending the root logical volume and filesystem resolved the installation failure.

Firewall management lockout

A private-network deny also matched firewall management. I recovered through the console and placed an explicit IT-to-firewall HTTPS allow above the block.

The main lesson: validate one layer at a time, test denied paths as well as allowed paths, and make recovery part of the design.

PROJECT OUTCOME

A stable foundation for the next phase.

INFRA-BASE-v1 establishes routing, identity, access control, and recovery behavior for future SOC experiments. Only this completed milestone is listed in the portfolio.
