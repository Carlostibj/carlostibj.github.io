THE OBJECTIVE

Build the infrastructure before the SOC

I built this environment because I wanted to understand the infrastructure a SOC depends on before jumping straight into alerts and detections. That meant getting routing, identity, DNS, Group Policy, permissions, segmentation, and recovery working first.

I configured each service, tested both allowed and blocked paths, fixed problems as they came up, and repeated the important checks after a controlled host reboot.

SKILLS DEMONSTRATED

Technical skills applied in this project

Proxmox virtualization, OPNsense routing and firewall policy, VLAN segmentation, DNS/DHCP, Windows Server AD DS, Group Policy, SMB/NTFS permissions, AGDLP group nesting, Ubuntu administration, Wazuh deployment, PowerShell validation, troubleshooting, and VZDump backup planning.

These are the tools and skills I actually used while building, testing, and fixing the environment.

THE DESIGN

Clear network roles and separation

OPNsense is the sole Layer-3 gateway for routed lab networks. Proxmox internal bridges provide Layer-2 connectivity. Servers and monitoring have dedicated networks; IT, Sales, HR, and Marketing each have a VLAN.

IMPLEMENTATION

Controls I configured

Service-based firewall policy

I allowed the internal services each network actually needed, then blocked unnecessary private-network access and kept Internet egress available where appropriate. Rule order mattered, so I tested it instead of assuming it was correct.

Centralized identity & policy

The homelab.internal domain uses departmental OUs, unique workstation names, and Group Policy. I also checked domain trust and DNS health from the clients.

Department file permissions

I used AGDLP-style group nesting so user membership and resource permissions stay separate. Department users can reach their own shares, while cross-department access is denied.

Monitoring foundation

I deployed Wazuh on a dedicated Ubuntu monitoring server and verified the service paths and dashboard access needed for the next phase of the lab.

Scope of this milestone: At this stage, Wazuh was only the monitoring foundation. Agent enrollment, Sysmon, network telemetry, and detection work were intentionally left for SOC01 and later projects.

A separate recovery copy

With the VMs shut down, I created ZSTD-compressed VZDump backups for all eight core systems on a dedicated external 2 TB ext4 disk. I treat those backups as the recovery copy and use local snapshots only for quick rollback.

I tested reboot and service recovery during this project. I did not claim a full restore test because I had not performed one.

ENGINEERING LESSONS

Issues I had to troubleshoot

Duplicate gateway ownership

Proxmox bridges carried gateway addresses that conflicted with OPNsense. I changed the bridges to Layer 2 only, leaving OPNsense as the sole routed gateway.

Marketing DHCP failure

The VLAN used the wrong OPNsense parent interface. Correcting the parent restored DHCP and stable connectivity.

Cloned Windows computer identities

Duplicate identities caused machine-account trust failures. I assigned unique hostnames, repaired secure channels, and documented generalization for future templates.

Group Policy processing stalled

The dynamic RPC firewall range was represented incorrectly. Correcting the rule restored normal gpupdate processing.

Wazuh installation ran out of storage

Ubuntu was not using the full virtual disk. Extending the root logical volume and filesystem resolved the installation failure.

Firewall management lockout

A private-network deny also matched firewall management. I recovered through the console and placed an explicit IT-to-firewall HTTPS allow above the block.

What I took from this project was simple: test one layer at a time, test blocked paths as carefully as allowed ones, and plan recovery before something breaks.

PROJECT OUTCOME

A stable base for the SOC work that followed.

INFRA-BASE-v1 became the starting point for SOC01. Once the infrastructure was stable, I could add security telemetry without wondering whether basic routing, identity, or access-control problems were causing the noise.
