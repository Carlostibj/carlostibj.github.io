Enterprise Proxmox Infrastructure Lab

Designed and built a segmented enterprise-style environment on Proxmox to practice systems administration, networking, identity, security monitoring, troubleshooting, and recovery. The completed infrastructure baseline, INFRA-BASE-v1, provides the foundation for future SOC detection and incident-response projects.

// architecture

Environment design

Virtualization

Dell Precision T5810 running Proxmox VE 9.2.2 with 64 GB RAM. Eight core infrastructure/client VMs are organized by role and isolated through dedicated Linux bridges.

Routing & segmentation

OPNsense provides routing, DHCP, firewall policy, and controlled inter-VLAN access. Department networks use VLANs 10/20/30/40 with explicit service allows followed by private-network blocks.

Identity & services

Windows Server domain homelab.internal provides AD DS, DNS and Group Policy. FILE01 provides department SMB shares protected with NTFS permissions and AGDLP group design.

Monitoring

WAZUH01 runs Ubuntu 24.04 and Wazuh on a dedicated Monitoring LAN, positioned for centralized endpoint telemetry and the next SOC phase.

// implementation

What I built

Active Directory

Created departmental OUs, users, Global Security groups, workstation/server placement, password and lockout policy, and workstation/user GPO baselines. Domain health was validated with dcdiag and DNS tests.

File services

Built FILE01 with a dedicated data disk and IT, Sales, HR, and Marketing shares. Implemented AGDLP using Global groups nested into Domain Local resource groups, with NTFS as the effective security boundary.

Firewall policy

Department clients can reach required AD/DNS/RPC, SMB, Wazuh, and Internet services while lateral department access is blocked. IT receives controlled administrative access and the unused Clients LAN is explicitly denied.

Recovery baseline

Created a dedicated 2 TB external ext4 Proxmox backup target and completed compressed VZDump backups of all eight VMs under the INFRA-BASE-v1 baseline.

// troubleshooting

Problems I diagnosed

Duplicate Layer-3 gateways

Solved

Proxmox internal bridges were configured with .1 addresses that conflicted with OPNsense. I moved the bridges to Layer 2 only so OPNsense became the sole gateway.

Cloned Windows identities

Solved

Cloned workstations shared computer identity information and developed domain trust failures. I repaired the secure channels, assigned unique hostnames, and documented Sysprep/generalization for future templates.

AD RPC firewall issue

Solved

Group Policy updates hung because the dynamic RPC range was not correctly represented in the firewall alias. Correcting the range restored gpupdate processing.

Management lockout

Solved

A broad private-network block also denied IT access to the OPNsense GUI. I recovered through the console and added a specific management allow rule above the block.

// validation

Acceptance testing

The baseline was not considered complete until the environment passed positive, negative, and recovery tests.

Identity

Secure-channel tests passed on FILE01 and all department workstations. Group Policy computer and user processing completed successfully.

Services

DNS resolution, department SMB access, Wazuh connectivity, and Internet access were validated from the appropriate networks.

Segmentation

Cross-department SMB, Monitoring-to-corporate SMB, and Server-to-client initiation tests were blocked as designed while approved traffic remained functional.

Recovery

Performed a controlled shutdown, rebooted the Proxmox host, started infrastructure in dependency order, and repeated core validation successfully.
